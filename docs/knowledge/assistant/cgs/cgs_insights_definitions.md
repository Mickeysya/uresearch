How every Insights page number is worked out. Every number is read LIVE on every page load and every chat question -- nothing on this page or in these answers is cached or computed in advance, so the two can never show different numbers for the same moment. The chat's own aggregate lookups (seat_release_outlook, almost_full_rooms, insights_summary, programme_breakdown, gender_comparison, key_status_overview, candidacy_expiry_distribution, length_of_stay_distribution, seat_status_by_block, return_outlook) read the exact same WorkstationStatistics functions the page's own charts read, so a chat answer and the page can never disagree by construction.

• **How many seats are in each state?** -- a grouped bar chart, one group per block (J2, N2), with Occupied/Available/Awaiting Key Return/Maintenance as side-by-side bars on one shared scale. Ask "seats by status per block" for the same numbers in words.
• **Which rooms are filling up?** -- occupied seats divided by capacity, per room, live; a room at or above {{almost_full_percent}}% is "almost full".
• **Male versus female rooms** -- a grouped bar chart, one group per gender, the same four statuses as above, counted and percented against that gender's own seats. Ask "male versus female occupancy" for the same numbers in words.
• **Seat release forecast** -- for each period (month, quarter or year, chosen automatically to fit; a "Drill down" button exists to see a finer grain for one period), the count of current seat holders whose candidacy expires then, plus seats whose termination vacate-by date falls then; Awaiting Key Return seats are deliberately NOT included, since they are already in progress, not a future release. The "Now" line is seats available today; the line above it is the MAXIMUM possible, not a prediction: an appeal can extend a candidacy by up to {{max_appeal_months}} months in total, which would remove that seat holder from the forecast entirely and push the real number of available seats lower than the chart shows.
• **Candidacy expiry buckets** (0-3, 3-6, 6-12, over 12 months) and **length of stay buckets** (under 6, 6-12, 12-18, over 18 months, from the seat's allocation date) -- counts of current seat holders in each range. Ask "when do candidacies expire" or "how long have students been in their seats".
• **Programme breakdown** -- current seat holders grouped by programme, top 8 plus an "Others" total. Ask "which programmes use workstations most".
• **Locker key status of seat holders** -- a grouped bar chart, one group per block, with Not Requested/Pending Collection/Collected/Return Pending as bars. Ask "how many keys are not requested" for the same numbers in words.
• **Key returns coming up** -- Return Pending keys due in the next 7 days, due in the next 8-14 days, and already overdue. Ask "when are keys due back".

Candidacy expiry, programme and allocation date are read for BOTH real student accounts and demo students, so every number on this page includes demo seat holders too -- this is different from the plain candidacy_expiring lookup, which (being older) counts real accounts only.
